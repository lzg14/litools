# litools 功能扩展计划

> ⚠️ **状态注记（2026-08 之后）**：本文档描述的 HTTP、屏幕、Markdown、Morse、代码格式化等模块已在后续精简重构中移除，当前代码仅保留 24 个核心模块（见 README 功能一览），本文档仅作历史参考。

**目标**：基于现有 9 大模块，规划实用新功能，保持单文件零依赖特色
**规划日期**：2026-08-02

**现有模块**：JSON / HTTP / 搜索 / SQL / 编解码 / 生成 / 文本 / 时间 / 屏幕

**已扩展功能**（2026-08-02）：
- **JSON 模块**：→ XML / XML→ / → Code（TS/Python/Go）/ → YAML / Schema / 合并 / 对比
- **SQL 模块**：IN 生成 / INSERT 解析 / SQL 格式化（关键字缩进）
- **编解码模块**：Base64 / URL / URL 解析器 / HTML / JWT / 进制 / Morse / Caesar / 二进制文本
- **生成模块**：UUID / Hash / 颜色（HEX/RGB/HSL/CMYK/对比度）/ 密码 / Lorem / 正则速查+解释器 / Cron / 代码格式化（JS/CSS/HTML）
- **文本模块**：处理 / 统计 / 简繁 / 大小写转换 / 翻译 / CSV / Diff / Markdown
- **时间模块**：时间戳 / 日期计算 / 计时器
- **屏幕模块**：屏幕信息 / 窗口信息 / 坏点检测

---

## 优先级说明

- P0：开发者高频刚需，实现简单
- P1：实用功能，有一定复杂度

## Phase 1: JSON 模块增强（P0）

### 1.1 JSON → YAML 转换
- 输入 JSON，一键转为 YAML 格式
- 支持反向：YAML → JSON
- 输出区可复制/下载
- **verify**: 输入 `{"a":1,"b":[2,3]}` 转换为合法 YAML

### 1.2 JSON Schema 校验
- 输入 JSON + Schema，校验是否符合 Schema
- 显示校验结果：通过/不通过 + 错误路径
- 内置常用 Schema 模板（分页响应、用户对象等）
- **verify**: 输入非法 JSON + Schema，显示具体错误路径

### 1.3 JSON 合并（Merge/Patch）
- 两个输入框：Base JSON + Patch JSON
- 支持 RFC 7396 Merge Patch 和 RFC 6902 JSON Patch 两种模式
- 输出合并结果
- **verify**: 合并两个嵌套对象，结果正确

### 1.4 JSON 对比（JSONDiff）
- 两个 JSON 输入框，对比差异
- 输出结构化差异（新增/删除/修改的路径）
- 可视化高亮差异节点
- **verify**: 对比两个有差异的 JSON，输出正确的差异路径列表

## Phase 2: HTTP 模块增强（P0-P1）

### 2.1 请求集合（Collections）
- 保存常用请求到 localStorage
- 支持命名、分组、删除
- 一键加载已保存的请求
- **verify**: 保存 3 个请求，刷新页面后仍可加载

### 2.2 环境变量
- 定义环境变量（如 `{{baseUrl}}`、`{{token}}`）
- 在 URL/Headers/Body 中使用 `{{变量名}}` 语法
- 支持多环境切换（dev/staging/prod）
- **verify**: 定义变量后，请求中 `{{baseUrl}}` 自动替换

### 2.3 响应可视化
- 自动检测 Content-Type
- XML/HTML 响应格式化高亮
- Image 响应内联预览
- **verify**: 请求返回 XML 时自动格式化显示

## Phase 3: 文本模块增强（P1）

### 3.1 Markdown 预览
- 左右分栏：左侧编辑 Markdown，右侧实时预览
- 支持常用语法：标题、粗体、斜体、链接、图片、代码块、表格、列表
- 使用原生实现，不引入外部库
- **verify**: 输入 Markdown 语法，右侧正确渲染

### 3.2 文本查找增强
- 支持正则替换（当前只有纯文本替换）
- 替换预览：显示每个替换的位置
- 计数：显示总匹配数/已替换数
- **verify**: 使用正则 `(\d+)` 匹配并替换为 `$1.00`，正确执行

### 3.3 行号显示
- 文本处理/统计模块的编辑器显示行号
- 点击行号可跳转
- **verify**: 长文本编辑器左侧显示行号

## Phase 4: 编解码模块增强（P1）

### 4.1 Morse 电码
- 文本 ↔ Morse 电码互转
- 支持字母、数字、常用标点
- 显示对照表
- **verify**: `SOS` 转为 `... --- ...`

### 4.2 Caesar 密码
- 支持 1-25 位移量
- 可暴力破解：尝试所有位移量，显示结果
- **verify**: 位移 3 时 `ABC` → `DEF`

### 4.3 二进制文本
- 文本 ↔ 二进制（每字符 8 位）
- 支持 UTF-8 多字节
- **verify**: `A` → `01000001`

## Phase 5: 生成模块增强（P1）

### 5.1 密码生成器
- 可配置：长度、大小写、数字、特殊字符
- 一键生成多个密码
- 密码强度评估
- **verify**: 生成 16 位含特殊字符密码，强度显示"强"

### 5.2 Lorem Ipsum 生成器
- 生成占位文本
- 可选：段落数/字数/句子数
- 支持中文 lorem（常用字随机组合）
- **verify**: 生成 5 段 lorem 文本，每段长度合理

### 5.3 正则表达式速查
- 常用正则表达式模板（邮箱、手机号、URL、IP 等）
- 点击直接复制或填入搜索模块
- 分类展示（验证、提取、替换）
- **verify**: 点击"邮箱"模板，正则填入搜索框

### 5.4 Cron 表达式解析
- 输入 Cron 表达式（如 `*/5 * * * *`）
- 显示人类可读描述（"每 5 分钟执行一次"）
- 显示未来 10 次执行时间
- 反向：选择频率生成 Cron 表达式
- **verify**: `0 9 * * 1-5` 显示"工作日每天 9:00 执行"

## Phase 8: 性能与架构（P2）

### 8.1 Web Worker 计算
- JSON 格式化/校验移到 Worker ✅ Blob-based Worker（>1MB 输入自动走 Worker，含超时回退）
- Hash 计算移到 Worker ⏸ Hash 使用 `crypto.subtle` 已是异步原生实现，无需 Worker
- 大文件搜索 Worker 化 ✅ 已有流式分块扫描（`srchStreamScan`），无需 Worker
- **verify**: 处理 50MB JSON 时 UI 不卡顿

### 8.2 虚拟滚动
- 搜索结果/历史记录使用虚拟滚动
- 支持 10 万+ 条目 ⏸ 已通过 `SRCH_DISPLAY_MAX=50000` 匹配行数上限 + HTTP 历史 50 条上限保证流畅，单文件架构下实现完整虚拟滚动收益有限
- **verify**: 加载 1 万条历史记录，滚动流畅

### 8.3 代码分割
- 将非核心模块（屏幕、SQL、编解码）按需加载
- 首屏加载提速
- **verify**: 首屏加载时间 < 200ms
- ⏸ 单文件架构（零依赖、可直接 file:// 打开）与构建期代码分割冲突；改用 `sessionStorage` 恢复会话 + `requestIdleCallback` 惰性初始化非关键逻辑
